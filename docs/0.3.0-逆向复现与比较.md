# 映序剪辑 0.3.0：逆向、复现与比较

日期：2026-10-13。本轮交付画面裁剪、水平/垂直镜像、亮度/对比度/饱和度调色及声音淡入淡出。原有多视频轨、叠化/淡黑转场、位置/缩放/旋转/透明度关键帧、本地自动字幕和 MP4 导出继续保留。

实际交付程序中的调色、裁剪与镜像预览（历史记录：`evidence/phase5/editor-0.3.png`，未随公开源码快照发布）

## 使用新功能

| 功能 | 操作 | 行为 |
| --- | --- | --- |
| 画面裁剪 | 选中视频或图片 → 右侧“画面裁剪与镜像” → 设置四边裁掉百分比 | 至少保留宽高的 2%；裁剪后完整适应画布，再应用位置、缩放与旋转 |
| 双向镜像 | 同一区域勾选“水平镜像”或“垂直镜像” | 两项独立，可同时开启；“还原裁剪与镜像”重置 |
| 基础调色 | 右侧“基础调色” → 调整亮度、对比度、饱和度 | 每项 −100 至 100，0 为原始画面；“还原调色”重置 |
| 声音淡入淡出 | 选中音频或有声音的视频 → “声音淡入淡出” | 以秒计，淡入与淡出总长不超过片段时长；和片段音量、转场共同生效 |

分割在淡入或淡出过程中发生时，会保留切点两侧原有的连续音量。面板出现“保留了分割前的音量包络”提示后，再修改淡入淡出会重新设置该片段包络。变速按比例改变包络时间，缩短片段会限制淡入淡出总长。保存、撤销重做和实际导出均保留这些设置。

画面裁剪不改变源素材文件，也不改变“时间与裁剪”中的源起点。调色和裁剪可用于主轨及叠层；裁成竖幅的叠层仍保留透明填充，下方轨道可以透出。自动字幕使用的本地混合音轨包含声音淡入淡出。

## 本轮逆向证据

固定分析目标是剪映 Windows `11.4.1.14443` 的 `videoeditor.dll`，SHA256：

```text
092a5f2c499015f4d3cb318990efa6fcd517cde86c0b3fd39433eae3389c9916
```

本轮完成 8 个原生函数的定向分析，重点包括 `Crop`、`Flip`、`MaterialAudioFade` 的构造或 JSON 更新入口、居中裁剪及线性插值入口。

| 已观察到的证据 | 映序中的实现 | 证据边界 |
| --- | --- | --- |
| `Crop` 更新四角的 X/Y 值；居中裁剪入口从单位矩形按宽高比缩入一维 | 用四边裁去比例表示矩形，换算成源图整数像素范围 | 这是独立工程表示，不宣称兼容原生四角对象和私有草稿 |
| `Flip` 有独立的 `horizontal`、`vertical` 布尔字段 | 水平和垂直镜像可独立开启 | 未据此推断剪映完整渲染管线的全部处理顺序 |
| `MaterialAudioFade` 有淡入时长、淡出时长和曲线类型字段；构造初始为零 | 秒制线性音量包络，支持分割、变速和裁短 | 原生时长单位及曲线类型枚举含义未确认；映序的秒制与线性曲线是独立设计 |
| 原插值函数只有 34 字节，对有序时间区间执行线性插值 | 现有画面关键帧使用线性插值 | 原函数外插及相同时间端点行为，与映序端点保持、有序验证的工程规则不同 |
| 安装资源 `FC/AmazingFeature_adjustColor` 的 Lua 参数映射及原始 GLSL | 独立实现亮度、对比度、饱和度；预览用独立 WebGL，导出用 65³ LUT | 仅覆盖这三个功能及受测条件，没有恢复所有调色与特效 |

原生分析记录由研究项目维护。交付包的比较报告是这些记录的副本；没有把复现代码当作剪映恢复源码。

## 怎样比较

比较对象分为原生计算、原始着色器、映序的实际媒体输出和桌面操作。每一层使用自己的证据，组件比较不能替代原软件完整编辑与导出流程的比较。

### 原生插值计算

从安装文件提取原插值函数的 34 字节机器码，在独立进程重放，针对有效、有序的区间和插值位置，与映序关键帧计算比较。共 512 组输入 × 5 个画面参数，即 **2,560 个数值**，最大绝对误差 **1.1102230246251565 × 10⁻¹⁶**。

这项结果限定在受测有效区间。原函数可进行外插；相同时间端点会产生 NaN 或 Infinity。映序会验证关键帧有序、避免重复时间，并在片段端点保持最近姿态，因而没有把原函数所有异常输入行为照搬。

报告：原生插值隔离重放（历史记录：`evidence/phase5/native-linear-replay.json`，未随公开源码快照发布）。

### 原始调色着色器与独立实现

参考端直接加载安装资源中**未经修改的原 GLSL**，在本机 GPU 执行，读取 RGBA8 像素。输入包含色块、灰阶、渐变、固定随机 RGB，参数包含零值、极值、亮度分段边界及固定随机组合。每组 256 × 128，共 **49 组、1,605,632 个像素**。

| 比较层 | 实际比较结果 | 范围 |
| --- | --- | --- |
| 原 GLSL → 映序独立 CPU `adjustRgb` | 49/49 通过；最大 RGB 通道误差 1/255；平均误差约 0.02423/255 | 对照参数映射、分段运算、执行顺序及最后夹紧 |
| 原 GLSL → 映序实际 `EditorColorPreview.render` | 49/49 通过；最大误差 1/255；平均约 4.15 × 10⁻⁷/255，仅 2 个 RGB 通道值相差 1 | 使用实际预览模块，非仅测试同一份 CPU 公式 |
| 不对称 RGBA → 实际预览模块 | 97 × 63 探针的上下方向与透明度逐值保留；中性不透明/半透明 RGB 最大差为 0 | 透明度覆盖 0、64、128、192、255，检查方向与 alpha 处理 |

GPU 高精度浮点、JavaScript 双精度及 RGBA8 量化可能带来末位差异。以上结果只覆盖受测图像和参数；大于 1280 的预览缩放、实际视频协议采样与完整桌面交互另行验收。

报告：独立 CPU 与原 GLSL（历史记录：`evidence/phase5/cpu-vs-original-shader.json`，未随公开源码快照发布）、实际预览与原 GLSL（历史记录：`evidence/phase5/preview-vs-original-shader.json`，未随公开源码快照发布）。

### 实际视频导出及误差

选择其中 6 组参数，调用映序真正的 `exportProject` 导出 H.264 MP4，再解码成 RGB 与原 GLSL 输出比较。同时单独运行相同 65³ LUT 的无损输出，分开观察 LUT 插值和视频编码产生的误差。

| 条件 | 无损 LUT 最大通道误差 | MP4 均匀色块内部最大误差 | MP4 均匀色块平均误差 |
| --- | ---: | ---: | ---: |
| 全部归零 | 1/255 | 2/255 | 0.680/255 |
| 亮度 +70 | 1/255 | 3/255 | 0.951/255 |
| 对比度 +100 | 1/255 | 4/255 | 0.698/255 |
| 饱和度 −100 | 1/255 | 2/255 | 0.625/255 |
| 混合：提亮、柔和 | 1/255 | 4/255 | 1.583/255 |
| 混合：压暗、鲜艳 | 3/255 | 3/255 | 0.742/255 |

6 组均通过事先记录的误差阈值。上表均匀色块统计排除了色块边缘；**不能用它代表整帧逐像素相同**。整帧保留了高频随机颜色区域，平均通道误差为约 **1.11–9.38/255**，主要包含 YUV 4:2:0 色度采样和 H.264 编码损失，未调色基线也有此差异。报告保留了完整帧、均匀色块及无损 LUT 的统计。

这里的参考是剪映安装包中的原调色着色器输出，不是通过剪映完整 GUI 导出的参考成片。

报告：实际导出、独立 LUT 与原 GLSL（历史记录：`evidence/phase5/export-vs-original-shader.json`，未随公开源码快照发布）。

## 映序自身验收

模型、媒体与分段读取测试 **31 项全部通过**：原有 24 项回归、新增 6 项功能测试和 1 项媒体协议字节级测试，未跳过。新增验证包括：

- 工程字段校验、旧工程兼容、编辑不修改撤销历史、调色参数边界。
- 实际裁剪加双向翻转后的四象限像素位置。
- 实际灰阶调色的亮度权重，以及调色竖幅叠层保留透明边距。
- 从真实波形测 RMS，与线性淡入淡出的独立解析预期比较。
- 在淡入内部切割后，切点两侧及淡出段的声音幅度保持连续。
- 自动字幕 WAV、普通 MP4、高级合成 MP4 三条路径都应用淡入淡出，并清理临时文件。

源码项目记录：`outputs/phase5-media-acceptance.json`，日志在 `work/phase5-media-test.log` 和 `work/phase5-legacy-test.log`。独立打包程序的新功能、原核心功能、样例、边界及连续定位回归均已通过，详见下文与验收记录。

## 桌面回归与新增边界记录

交付程序已实测新增功能 10 项、多轨/转场/关键帧/自动字幕 13 项以及包内新旧演示 6 项；结果见相应验收文件。自动字幕使用实际口播生成并写入，再与画面共同导出有声 MP4。

连续切换同 ID 的新旧工程时，发现并修复旧媒体回调残留导致调色画布隐藏的问题；同时修复本地媒体协议的 Range 响应。新增真实定位验收覆盖 4 次打开工程、20 次跳转，直接核对视频的 currentTime、可寻址区间和当前帧像素，不只观察播放头。Range 101–257 返回 206 与准确的 157 字节；HEAD 返回完整长度但不含正文。相关记录见 连续重开与定位（历史记录：`evidence/phase5/phase5-preview-reuse-acceptance-packaged.json`，未随公开源码快照发布）。

另外修复并验证两项边界：103 个片段的工程中，叠层仍正确显示在后段主轨上方；素材在相同路径被换成不同尺寸、时长、音轨的视频后，重新打开工程会更新媒体事实，保留工程中的素材标识与用户名称。裁剪预览以新尺寸计算，并写入保存文件。

在后一项受测 BT.709 视频中，裁剪预览与同一 Chromium 的未裁剪源视频参考对应区域最大通道差为 0；实际导出与 FFmpeg 解码的源视频对应区域最大差为 2。**Chromium 原生截图与 FFmpeg 解码之间仍观察到最大 56/255 的通道差**，已单列记录，不属于前述原始 RGBA 色卡的 1/255 误差范围。色彩标签、解码器与显示色彩路径尚未统一，不能宣称预览和成片逐像素一致。第一次把两条不同色彩路径直接比较而失败的记录保留，没有扩大原验收容差。

## 尚未证明或实现的部分

本轮没有验证剪映整个 GUI 的全部交互，也没有完成两款软件端到端导出的一致性比较；`.yxproj` 是独立工程格式，不宣称兼容剪映私有草稿。组件比较的通过数不是完整逆向率。

仍待后续实现或扩大验证的项目包括进阶调色、滤镜、蒙版、混合模式、其它转场、关键帧缓动、曲线变速、降噪及其它 AI 功能，以及长片、大型工程、不同字体、其它机器和编解码器的表现。当前导出支持 H.264/AAC MP4；有损编码、LUT 近似和预览缩放意味着预览与成片不保证逐像素一致。

开发用原始报告来自外部研究项目的 `outputs/phase5-reference/`，插值原始记录为该研究项目 `outputs/phase5-interpolation-oracle.json`；外部研究项目不随本公开源码快照发布。阅读本文件时，可区分已保留的相对报告链接与未随快照发布的历史记录路径；所有后续范围以 [功能与验收范围](scope-and-acceptance.json) 为准。
