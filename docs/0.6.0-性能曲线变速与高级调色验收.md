# 映序剪辑 0.6.0 · 性能、曲线变速与高级调色

日期：2026-10-15。文中项目路径均相对于仓库根目录。本轮按高分辨率蒙版、曲线变速、高级调色的顺序完成开发与验证。原测试环境中的 0.5.0 独立程序保留在原目录，未随本公开源码快照发布。

## 高分辨率蒙版导出

0.5 会对每一输出帧重复处理静态图片的裁剪、调色、蒙版和缩放，并在全尺寸像素上反复求透明度表达式。本轮把静态处理缓存一次；运动视频复用精确覆盖图，再乘保留的源 alpha；逐帧透明度改为小查表。保留原公式和浮点顺序、原画质设置、SDR 标签及声音。

| 同条件短片 | 0.5 / 秒 | 0.6 / 秒 | 提速 |
|---|---:|---:|---:|
| 1080p 图片蒙版，12 帧 | 36.07 | 6.45 | 5.59× |
| 4K 图片蒙版，6 帧 | 77.19 | 12.33 | 6.26× |
| 1080p 运动视频蒙版，12 帧 | 35.22 | 6.40 | 5.50× |
| 4K 运动视频蒙版，6 帧 | 70.57 | 12.66 | 5.57× |

比较使用同一输入、帧率、CRF18 和两条编解码／滤镜线程，机器为 Ryzen 9 7945HX Windows x64。四组最终 MP4 的解码 RGB 与 PCM 均逐字节相同，MP4 容器文件自身哈希不要求相同。这些短片包含固定启动开销，不是所有长片、轨道数量和机器的速度承诺。最终候选复核与首轮耗时略有差异，表格采用最终引擎哈希下的复测数值。保留的 7.4 秒、720p 旧演示工程用本轮引擎实际导出约 30.50 秒，RGB、PCM 及 MP4 文件 SHA-256 均与 0.5 成片完全相同；新功能演示长约 4.94 秒，实际导出约 28.05 秒。这两次完整工程运行处于并发验收环境，不作为隔离性能基准。原始逐阶段耗时、视频及哈希保留在 `outputs/phase8-performance.json` 和本轮对比页。

## 曲线变速

速度控制点定义在源素材进度上，速度在相邻控制点之间线性变化，范围 0.25–4 倍；输出时间用解析积分计算，再反解得到任意时间线时刻的源时间。独立预设和自定义速度图可编辑 2–32 个点。它不是关键帧位置缓动，也不宣称恢复剪映原速度预设。

更换速度方式保持源素材跨度，按新片长重定时动画和音量包络；分割、修剪保留对应曲线区间与动画轨迹。视频源入点、叠层起点和分割点可位于非整帧位置，输出按全局帧格采样，避免局部帧时钟重置造成错帧或黑帧。五组实际视频、398 个输出帧的源帧编号全部正确，非整帧分割前后最终 RGB 字节完全一致。时间线预览、原声、导出和字幕识别使用同一源时间映射。

音频采用短输出片段、源前后上下文、恒速保音调处理与短重叠融合，按采样落位。直接连续调速曾在极端曲线中出现超过 0.1 秒的内部事件漂移，因此没有作为最终方案。最终生产路径四条曲线、56 个不同频率事件（含源入点后 8ms、出点前 14ms）最大偏差为 **21.5ms**，长度误差小于一个 16kHz 采样，无长静音断裂。此结果不等同音乐听感无损或任意长片逐采样同步。

## 高级调色

在已有 FC 基础亮度／对比度／饱和度后，新增曝光 EV、色温、色调、高光、阴影、白色／黑色色阶、主／红／绿／蓝分通道曲线，以及红、橙、黄、绿、青、蓝、紫、洋红八色段的 HSL。曲线支持 2–16 个点，使用分段线性映射。默认值保持旧版像素，CPU 和预览 GLSL 共用公式定义；输出仍使用 65³ LUT。

CPU 四项与真实 GPU 十一组、360,448 个像素通过，GPU 对 CPU 最大通道差为 **1/255**，默认值与 0.5 GPU 逐字节相同；源 alpha 和上下方向另外检查。实际 MP4 五组静态调色色卡、每组 32 色块，最大内部采样差 **3/255**、平均差 0.615–1.229/255。这是色卡内部采样结果，不能作为全部运动画面的最大误差。

新功能综合工程把高频 `testsrc2` 运动视频、曲线变速与高级调色叠加。四个时点的每 4 像素网格抽样平均差约 3.47–4.14/255，峰值为 **169/255**；进一步逐像素独立诊断的峰值为 **196/255**。两者的采样覆盖不同，不能把网格峰值当作全部像素的上界。高频纹理、色度边缘及有损压缩的差异保留在报告中。

诊断把同一浏览器解码 RGBA 输入交给 CPU／GPU 调色，全像素最大通道差不超过 **1/255**。UI 按未调色输入的邻域变化预先选择平坦区域，每帧覆盖超过 4,500 个通道，平均差约 0.95–1.02/255、最大 **12/255**；独立诊断改用 FFmpeg 未调色源的完整 9×9 邻域筛选，平坦区域平均差约 1/255、最大 **13/255**。筛选方法不同，两个结果分别记录。具体值和样本数见 `phase8-ui-packaged/acceptance.json` 与 `phase8-ui-color-diagnosis/diagnosis.json`。

独立实验先确认浏览器与成片使用的源帧编号精确一致。调色前，Chromium 与 FFmpeg 对同一 4:2:0 原片的 RGB 重建已经存在尖锐边缘差异，而独立源平坦区域最大差仅 1/255；同一浏览器 RGBA 输入的 CPU／GPU 调色仍相差不超过 1/255。把 FFmpeg 源 RGB 独立调色后再与成片比较，可以进一步看到再次 4:2:0 编码带来的误差。控制实验中，CRF0 的 4:4:4 往返最大差 1/255，4:2:0 往返最大差 35–36/255、平坦区域不超过 2/255。证据支持大峰值主要来自两种解码器的色度重建及有损再编码，没有观察到全局范围／矩阵失配。静态色卡、平坦区域、网格抽样和全像素结果均保留各自的采样定义，不把色卡的最大 3/255 套用于整幅运动画面。

高级算法为独立 SDR 实现。非常陡峭或极密的曲线点可能受 65³ LUT 插值限制；常规曲线的测试不能证明任意锐折完全逐像素一致。HDR、任意图片 ICC 和广色域仍沿用既有边界。

## 编辑保护及最终验收

打开、演示或恢复工程期间会暂时锁定原工程编辑，防止异步加载结束覆盖期间修改；普通素材导入仍可正常写入工程。曲线片长可能是非整毫秒，末尾关键帧也按实际片长限位。

源版 **50/50 自动化测试**通过，含奇数尺寸运动蒙版、映射／分割、工程兼容和取消清理。交付包与实际程序的最终验收如下；各行的计量单位不同，不把像素、时间点与操作步骤相加为一个测试总数。

本轮没有进行原剪映 GUI 的曲线／高级调色整机对照，也没有把独立算法描述成剪映全功能等价。曲线光流补帧、任意 Bézier 速度手柄、复杂特效、云端 AI、专业示波器／色轮／外部 LUT 导入等仍在后续范围。
