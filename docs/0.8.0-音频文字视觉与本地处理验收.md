# 映序剪辑 0.8.0 · 音频、文字、视觉与本地处理验收

本轮在映序剪辑 0.7 的时间线和工程管理基础上，补充独立音轨、文字排版、专业调色与视觉处理，以及显式本地素材转换。实现与验收面向 Windows x64 独立程序。本软件为独立实现，功能名称相近不表示与剪映使用相同算法。

**交付总记录以源码项目的 `outputs/final-acceptance-v0.8.0.json` 为准。** 全量单元测试、包内报告数、检查数、文件数量与 SHA-256 均由最终门禁生成，本文不使用开发过程中的暂定总数。包内静态证据位于 [evidence/phase10/index.json](evidence/phase10/index.json) 及对应报告；失败、运行中或源码变化的中间报告不作为通过证据归档。

## 交付内容与试用

正式程序为 `outputs/映序剪辑-0.8.0-win-x64/映序剪辑.exe`。源码项目根目录的 `启动映序剪辑.cmd` 指向本轮版本。独立包包含 Electron、FFmpeg/FFprobe、本地 Whisper，以及 ONNX/U2NetP 推理所需文件，保留整个文件夹一起移动，无需另装 Node.js 或 Python。旧版包与旧验收记录保留。正常版本共用用户数据目录；试用新版前先保存并关闭旧版，验收没有关闭用户已有试用窗口。

通过“打开”选择包内 `resources/app/assets/demo/` 的 `.yxproj`，源码对应 `assets/demo/`。六个工程分别为：

| 工程 | 主要内容 |
| --- | --- |
| 多轨与动画演示 | 视频叠层、转场与变换关键帧 |
| 调色与声音演示 | 基础调色与声音参数 |
| 蒙版与缓动演示 | 矩形/椭圆蒙版与缓动 |
| 曲线变速与高级调色演示 | 源时间映射、速度曲线及高级调色 |
| 自由时间线与素材管理演示 | 自由主轨、空隙和素材管理 |
| 音频文字与视觉工作台演示 | 本轮音轨、独立文字、字幕、专业调色和动画蒙版 |

新示例工程 [音频文字与视觉工作台演示.yxproj](../assets/demo/音频文字与视觉工作台演示.yxproj) 为 1280×720、30 fps，含 3 个素材、5 个片段、3 条字幕、2 个独立文字、2 条音轨及 1 个编组。源码项目的新成片为 `outputs/音频文字与视觉工作台演示-v0.8.0.mp4`，正式包对应 `演示成片/音频文字与视觉工作台演示.mp4`。成片实际存在、元数据与哈希由最终交付清单确认。旧的自由时间线成片仍保留，不用它代替本轮新示例。工具栏“演示”仍打开内置基础示例。

## 本轮功能及操作范围

| 范围 | 实现与操作 |
| --- | --- |
| 声音与音轨 | 最多 8 条独立音轨，波形、采样峰值/RMS、静音、独听、增益与锁定；原声分离，片段降噪与响度处理，本地录音。试听与成片使用同一混音含义。锁轨保护已有片段及新增、粘贴和移入目标轨。 |
| 字幕与独立文字 | 每条字体、字号、粗体/斜体、颜色、位置、对齐、换行宽度、字距、行高、背景、描边、阴影、旋转、缩放与透明度；文字可重叠，独立文字与字幕分开保存。支持批量样式、原子批量校对、字面查找替换和整体平移。 |
| 专业调色 | Bézier RGB 与独立 Y 色调曲线，Lift/Gamma/Gain/Offset 色轮、分区色偏、六维 HSL 选区，以及本地 1D 或 3D Cube LUT 导入。LUT 数据随工程保存。 |
| 视觉处理 | 色度抠像、去溢色、边缘平滑、12 种透明混合模式；蒙版扩张、圆角及中心/尺寸/旋转/羽化等关键帧。 |
| 本地素材处理 | 运动补偿补帧、两遍视频防抖、明确的 PQ/HLG→SDR 转换，以及 U2NetP 显著前景分割；各功能生成新素材，原文件保留。 |
| 编辑与交付 | 持久编组/解组、素材库源入出点、MP4 质量/码率和编码器选择、区间导出、48 kHz 立体声 WAV；原尺寸/1080/720/540 预览代理及缓存预算管理。 |

Bézier 控制柄用于本轮色调曲线；速度曲线仍为原有速度点和线段，不应把两者混为一项。专业调色、抠像、混合和蒙版的参数定义与算法差异见 [专业调色与视觉效果实现说明](专业调色与视觉效果算法说明.md)。

文字样式按整条文字保存，SRT 只输出字幕文本和时间，不包含独立文字及视觉样式。未设置新样式的旧工程保留此前字幕路径；启用单条样式或独立文字后，预览和导出使用同一个 Canvas 排版模块。更改画布高度时，字号、字距、背景内边距、描边和阴影像素参数同比缩放，归一化位置、对齐、旋转等保持。

多来源音轨的编组横向拖动会保留各自原轨，不能用一次垂直拖动把它们静默合并到一个轨道；需按单轨选择后移轨。编组的共同移动、删除、复制/粘贴和撤销已测试。混合选择主轨与其它类型时，仍需关闭主轨磁吸以保留相对时间。

录音与声音电平不等同于专业测量仪表。电平采用 48 kHz 重采样的 sample peak/RMS，不是 true peak 或 LUFS 计量；响度处理使用独立的响度算法。录音采集夹具和回归结果见最终记录，未完成所有实体麦克风、声卡与驱动组合的兼容验证。

## 文字预览与最终成片的误差

受测为本机 Windows 字体环境、320×180、25 fps、30 帧，包含中文多行、字距/行高、重叠、背景、描边、阴影、旋转、缩放和不存在字体的系统回退。共享 Canvas 预览栅格与透明 PNG/FFV1 文字层逐像素 RGBA 相同：检查 1,728,000 个像素，最大通道差为 0。

经过最终 MP4 合成和 H.264 4:2:0 编码，误差不再为零。RGB 误差单位为 0–255 码值；P95 按所有 RGB 通道的绝对差统计。

| 受测画面 | RGB 均差 | P95 | 最大通道差 | PSNR |
| --- | ---: | ---: | ---: | ---: |
| 纯文字/字幕与黑底 | 1.241 | 8 | 91 | 34.34 dB |
| 真实背景片段与文字 | 2.135 | 8 | 75 | 34.59 dB |

直接在导出 IPC 指定缩小画布，与先通过界面应用相同画布再导出，最终解码 RGB 逐值相同。纯文字工程无视觉片段时，导出的 30 帧视频和静音音轨也已确认；未把新增文字输入误映射成声音。

以上只覆盖报告列出的素材、时间和字体环境。字体边缘、色度抽样、压缩、显示器 ICC 与显示缩放仍可能带来差异，不能把“共享文字层 RGBA 最大差 0”写成“最终成片或屏幕完全一致”。专业调色也区分直接数学值、65³ LUT 近似和实际 GPU/FFmpeg 路径；受测 HSL 边界对直接公式最大差 14/255，GPU 对实际 FFmpeg LUT 最大差 1/255，具体条件见算法说明。

## 预处理的实际验证与边界

“运动补帧”使用 CPU 运动补偿插值。受测 12 fps、1.5 秒素材转换为 30 fps 后恰为 45 帧，保留音轨和有效时长，并验证 SDR 工作标签。修复了插值队列与输出时长截断造成尾帧丢失的问题；首尾缺乏未来帧时使用边界保持。它不是神经网络补帧，遮挡与快速运动的质量仍需检查生成结果。

“视频防抖”先生成真实运动分析，再执行相机路径平滑和静态放大裁边。受测静态纹理加合成相机抖动时，中央区域相邻帧平均绝对差从 29.802 降至 15.348，比例 0.515。这个结果说明该夹具中的画面运动减少，不表示任意实拍素材均可改善约 48.5%，也不恢复运动模糊或保证消除滚动快门。

“HDR 转 SDR”从独立文件入口选择素材，普通剪辑仍使用 SDR 准入规则。只接受明确的 BT.2020 原色/矩阵与 PQ 或 HLG 标签，Dolby Vision 动态元数据不在支持范围。使用 Hable 色调映射、100 nit 参考白和可配置峰值，输出 BT.709 原色/矩阵、sRGB 传递函数、全范围视频。PQ/HLG 的合成标签夹具均完成转码和输出校验，未证明所有拍摄设备、高光内容和动态元数据的色调映射质量。

所有转换都写入独立目录，并有转换参数/元数据记录。受测原文件 SHA-256 保持；取消会停止处理并删除当前任务自身的未完成目录，保留先前成功结果。生成素材需要像普通素材一样随工程归档，不是可以随意删除的预览代理。

## 组合示例与动态蒙版性能记录

交付示例画布为 1280×720、30 fps，包含专业调色、曲线变速、文字、两条音频轨与动画蒙版混合叠层。交付前，使用 1600×900 图片作为动态蒙版叠层的首次导出尝试超过 600 秒测试上限，未得到导出效率通过结论；失败原始记录单独保留在 [高分辨率尝试](evidence/phase10/phase10-delivery-demo-highres-attempt.json)，不计入通过检查数。该次运行期间另有音频计量修复，记录也保留了源哈希变化，不能作为最终包完全不变的一次验收。

正式示例保留 720p 画布与全部效果，叠层改用本项目原始纹理的 320×180 缩小副本。最终示例的实际导出和全流解码以 [交付示例报告](evidence/phase10/phase10-delivery-demo.json) 为准。静态蒙版缓存优化不意味着大尺寸动态蒙版已经快速；此场景仍是明确的性能限制。

## 尚未完成与比较范围

- 本轮没有新增原剪映 GUI 的全机、全功能比较。此前原软件整机对照仅适用于历史报告列出的合成短片和调色条件；本轮主要是独立软件的算法、真实 UI、IPC、媒体处理和打包回归，不宣称全剪映功能或算法一致。
- 尚无逐字范围富文本、逐词高亮、任意 Bézier 速度控制柄、专业示波器、复杂特效/商业模板库与云端 AI；不兼容剪映私有草稿格式。
- HDR 仅可先转为 SDR 中间素材；未提供原生 HDR/广色域编辑、监看、导出、杜比视界或任意图片 ICC 色度管理。
- U2NetP 是通用显著前景模型，视频逐帧处理，不是指定对象的时序跟踪；头发、透明边缘、遮挡和帧间稳定性有质量边界。当前透明视频链限定 VP9 alpha，静态透明图为 PNG。
- 本轮未重跑端到端高分辨率导出速度基准。历史 0.6 约 5.5–6.3 倍蒙版提速仅适用于其受测条件；不能直接套用到新增特效、文字与混音组合。长片、多机器、更多素材和实体采集设备仍未全面验证。
- 区间导出目前先处理完整时间线；缓存预算是软上限，正在引用及撤销历史需要的缓存会受到保护，清理后可能仍超过预算。生成的原声分离、AI 和转换素材不作为可丢弃代理清理。
